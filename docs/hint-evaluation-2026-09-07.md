# 힌트 소스 실험 및 선택 (2026-09-07 KST)

현재 15,199개 제목 스냅샷에서 SHA-256 고정 시드로 100개를 무작위 추출했다. 친숙한 64개만 골라 검사하지 않았다. 표본과 요청 시간, 결과는 인접 JSON에 보존한다. 시간은 UTC, 보고서 날짜는 한국 시간이다.

| 방법 | 100개 표본 결과 | 해석 |
|---|---:|---|
| 검토된 64개 카드 | 0 | 전체 목표 목록을 대체할 수 없음 |
| 한국어 위키백과 정확한 제목 | 설명 후보 51 | 동명 문서일 수 있음; 사실 정확도 검증 수가 아님 |
| 위키데이터 P8885 | 명시적 연결 18, 한국어 설명 14 | 정체성 연결에는 유용하나 단독 커버리지가 낮음 |
| 위키백과 + P8885 동일 엔티티 | 9 | 나머지 42개가 틀렸다는 뜻은 아님 |
| 기존 나무위키 추출기 | HTTP 99, 제목 일치 91 | 이미지 파일명·미완성 메타 설명·인용문을 성공으로 잘못 셈 |
| 수정한 나무위키 추출기 | 분류 또는 설명 91, 분류 87, 설명 발췌 81 | 응답한 같은 제목 원문에서 발췌. 전부 좋은 정의라는 뜻이 아님 |

수정 후 8개는 리다이렉트/제목 불일치로 제외, 1개는 원문 응답 실패였다. 의미가 더 넓은 페이지(예: 지리학자→지리학)를 자동으로 같은 문서라고 승인하지 않았다. 일부 발췌는 정의 대신 별칭·부가 설명이어서 추가 개선 여지가 있다. 전수 검증, 수백만 문서 커버리지, 실제 사용자 환경의 91% 성공률을 주장하지 않는다.

별도의 Cloudflare 원격 미리보기에서 게임 서버→기존 리더 요청은 502(내부 원인 403)였다. 반면 PC→리더 경로는 원문을 반환했다. 403 이후 해당 서버 경로의 추가 시험은 중단했다. 로컬 HTTP 200만으로 운영 서버의 성공을 주장하지 않는다.

## 적용 정책

- 목표 선정과 힌트 유무를 분리한다. 랜덤·라운드·일일 목표에 15,199개 스냅샷을 사용한다. 현재 나무위키 전체 문서 수를 뜻하지 않는다.
- 검토된 64개는 빠른 캐시처럼 유지한다. 다른 목표는 과반수 요청 이후 웹/프로그램이 정상적인 힌트 준비 요청을 보낸다.
- Sites의 서버 코드만 원문을 추출한다. 클라이언트가 보낸 설명은 저장·공개하지 않는다. 게임 서버는 원문을 반복 요청하지 않고 서버 소유 캐시만 읽는다.
- 문서 제목·분류·본문의 짧은 발췌·출처만 D1에 저장한다. 원문 HTML·이미지는 저장하지 않는다. 양성 7일, 음성 5분, 25초 동시 준비 잠금, 항목 4KiB 제한. 만료 정리는 요청당 100행으로 제한한다.
- 1단계 분류, 60초 후 새 과반수에 2단계 설명. 설명만 있을 때는 1단계 설명으로 끝낸다. 분류만 있으면 빈 2단계를 제공하지 않는다.
- 라운드에 저장한 스냅샷은 모든 참가자에게 동일하다. 미공개 설명·스냅샷은 참가자에게 전송하지 않는다. 준비 토큰은 현재 과반수 투표·라운드에만 유효하다.
- 차단 회피, IP 교체, 숨은 브라우저, CAPTCHA 해결, 위키백과 링크를 나무위키 경로로 간주하는 작업은 하지 않는다. 접근 실패는 음성 캐시와 사용자 안내로 처리한다.
- 수백만 건을 미리 다운로드하거나 앱에 넣지 않는다. 실제 요청된 목표 중심의 캐시이므로 목록 확장과 앱 용량을 분리한다. 대규모 운영은 저장소 한도·요청량을 측정한 뒤 별도로 설계해야 한다.

## 재현

`node scripts/benchmark-hint-sources.mjs` (초기 HTTP/위키백과/위키데이터), `node scripts/benchmark-namu-extraction.mjs` (수정 추출기). 공개 원문을 다시 조회하는 명시적 실험이므로 CI에서는 실행하지 않는다. 거부 응답은 중단하며 실제 결과는 시점·환경에 따라 달라진다.
